# Easy3D architecture

This document describes implemented architecture. Future systems remain governed
by `MASTERPLAN.md` and must not be inferred as available from this document.

## Scene and entity ownership

Each public Python `Scene` exclusively owns one native C++ `World`. A `World`
stores entities in reusable slots and is authoritative for entity lifetime and
native entity state. A Python `Entity` is a small reference containing:

- a strong reference to its owning Python `Scene`, so the native world cannot
  disappear while a live wrapper still needs to query it; and
- a native `EntityHandle` with `world_id`, slot `index`, and `generation`.

The numeric public `Entity.id` combines generation and slot index. It is unique
within a scene for the lifetime of that entity, but it is not a network identity
and must not be serialized as one. Networking will assign separate stable IDs.

Destroying an entity increments the slot generation before the slot is reused.
Clearing a scene increments every live slot generation. Native access validates
all three handle fields, so stale and cross-world handles cannot alias newly
created entities. `is_alive` is a non-throwing probe; other stale-handle access
raises native `InvalidEntityError`, exposed to Python as a `ReferenceError`
subclass.

Entity names, `enabled`, `visible`, local TRS, hierarchy links, cached world
matrices, transform-dirty state, and optional singleton `RenderComponent` and
`LightComponent` values are native slot data. Component teardown occurs on
entity destruction, scene clear, and slot reuse.

Parent changes validate world ownership and reject cycles. Local matrices are
composed as translation × quaternion rotation × scale. Descendant caches are
invalidated recursively when any ancestor changes. Optional keep-world
reparenting calculates a new local TRS from the inverse parent matrix. Destroying
a parent detaches direct children with their world transforms preserved.

GLM 1.0.1 is an immutable, private implementation dependency for matrix and
quaternion operations. Public native and Python boundaries use Easy3D-owned
types so dependency representation changes cannot leak into gameplay code.

## Renderer and mesh resource ownership

`MeshData`, `Vertex`, `Bounds`, `Color`, and `Material` are Easy3D-owned native
types with no bgfx handles in their public representation. Mesh validation
rejects empty/non-triangular index streams, out-of-range indices, non-finite
attributes, zero normals, and invalid color channels. Built-in triangle, cube,
horizontal plane, and UV-sphere generators use counter-clockwise front faces,
right-handed coordinates, +Y up, and 32-bit indices.

The Win32 backend delegates to a private `BgfxRenderer`. Its internal
`MeshLifetimeManager` converts validated mesh data into one immutable vertex
buffer and 32-bit index buffer per resource. Move-only GPU mesh owners destroy
index and vertex handles deterministically. Renderer shutdown clears draw
items, releases all mesh buffers, programs, samplers, and material/lighting
uniforms, submits a final release frame, then shuts down bgfx before SDL destroys
the window.

The solid and textured shaders multiply vertex/texture RGBA by a material color
and optionally apply ambient plus Lambert directional illumination. The vertex
stage transforms normals with the inverse-transpose world matrix. Material state
controls lit/unlit selection, color/depth writes, `LESS` depth testing, and
counter-clockwise back-face culling. Easy3D-owned shader sources are
authoritative; reviewed D3D11 DXBC headers generated by the immutable-pinned
bgfx `shaderc` are committed so normal builds do not compile the complete
shader-tool dependency stack.

Phase 1.3 validation still provides an explicitly enabled native diagnostic
scene. Ordinary `Game` instances now pass their loaded native `Scene` to the
renderer. Each frame the renderer walks live handles, skips inactive, disabled,
invisible, and non-renderable entities, composes native world transforms, and
submits primitive meshes or OBJ parts. CPU mesh/model/image resources are
immutable and shared; private GPU buffers are cached by resource identity, while
GPU textures are keyed by image identity plus sampler settings. No per-frame
Python draw loop is involved.

Mesh AABBs are cached beside renderer resource identity. Each frame builds a
frustum from the capability-correct projection × view matrix and conservatively
tests a transformed bounding sphere before any texture upload or draw. Visible
items are grouped by mesh/material/texture. Groups of at least two uniformly
scaled instances use transient 4×4 model-matrix instance data and dedicated
instanced vertex programs; non-uniform scale uses the normal single-draw program
with an inverse-transpose matrix. Frame counters are published through a
sequence-protected set of atomics so Python monitoring cannot observe fields
from different frames.

## Camera and projection

The native `Camera` stores finite position, normalized quaternion orientation,
projection mode, vertical FOV or orthographic height, and positive near/far
planes with `far > near`. Its
right-handed basis uses local forward -Z, right +X, and up +Y. `look_at` rejects
coincident targets, zero up vectors, and direction/up parallelism.

`Matrix4` is an Easy3D-owned, column-major 4×4 value. Camera view matrices map
world space into camera space; perspective and orthographic projection both
select `[0,1]` depth for D3D or `[-1,1]` homogeneous depth when a future backend
reports that capability. Projection aspect is calculated from the current pixel viewport, not the
logical window size. SDL resize/pixel-size events update the bgfx swap chain and
view rectangle; each submitted frame rebuilds projection from the current pixel
width and height.

Python `Camera` is a typed configuration facade backed by the same native
view/projection/look-at math. It exposes mutable `Vec3` position/Euler rotation
and matrix tuples. Each native `Scene` owns a camera value, initialized to a
usable look-at default. Python assignment copies a `Camera` into the scene, and
the renderer reads it each frame while still deriving aspect from the current
pixel viewport. Cameras are not entities or components in this baseline.

## Lighting and debug rendering

Each world slot may own one validated `LightComponent`. Ambient components
accumulate color × intensity. The first enabled directional component derives a
world-space direction by rotating local -Z through the entity hierarchy; later
directional components remain stored but are not blended by the baseline. A
default ambient/directional rig remains for kinds that have no explicit scene
component, preserving visible output for simple scenes. Light and render
component mutation shares the same running-game guard as transforms.

`Scene` also owns persistent `DebugLine` values outside the entity registry.
The renderer groups them by depth-test mode, allocates frame-local transient
vertex buffers, and submits unlit line primitives through the solid program.
This establishes debug visualization without persistent GPU handles or
per-frame Python callbacks. Scene clear releases both entities and debug lines;
camera configuration remains reusable.

Phase 6.1 keeps quality selection above bgfx as four immutable engine presets.
The low path retains the baseline direct diffuse shader. Medium and above add a
camera-aware metallic/roughness specular approximation, render the 3D pass to
an RGBA16F/D24S8 framebuffer, then tone-map, gamma-correct and optionally FXAA
in one fullscreen pass. High and Ultra prepend a single R32F/D24S8 directional
shadow pass at 2048 or 4096 pixels. The shadow camera tracks the scene camera
with a bounded orthographic volume and 3x3 PCF sampling.

Render-target creation is capability-checked. A failed HDR target routes the
main view directly to the swap chain and disables postprocessing/FXAA; a failed
shadow target binds a white fallback texture and disables shadow sampling.
Resize recreates only the window-sized HDR target. bgfx continues to own handle
retirement, while Easy3D destroys framebuffers, textures, uniforms and programs
before renderer shutdown. Atomic latest-frame stats expose the features that
actually became active.

## Retained 2D overlay

The scene owns validated `UiElement` values independently of entity handles.
Each has a monotonic scene-local ID, kind, nine-point anchor, viewport-pixel
rectangle, z-order, color and optional immutable image/text state. Scene clear
releases UI items and their CPU texture-cache references. Python wrappers retain
callback and layout policy, while the renderer reads one stable native vector
after the gameplay callback; no Python draw call occurs for an element.

The renderer's fourth ordered bgfx view targets the swap chain after shadow,
3D, and optional postprocess views. It sorts visible items by `(z_index, id)`,
builds frame-local triangle lists, alpha-blends panels/sprites/text, and exposes
separate UI submission counters. PNG/JPEG sprites share the renderer's private
GPU texture lifetime manager. Text uses stb_truetype once at startup to bake
printable ASCII from bgfx's pinned Roboto Regular data into one private RGBA8
atlas; each label submits its glyph quads together.

Button hit testing remains in the friendly Python layer because callbacks are
Python objects, but it uses the exact anchor/pivot equation and the native
engine's atomic current framebuffer extent. SDL pointer coordinates and deltas
are scaled from logical units to framebuffer pixels before entering `Input`.
Dispatch occurs inside the frame mutation boundary before scheduler phases and
chooses only the topmost enabled visible button on the press edge.

## Input ownership and frame boundaries

`Engine` owns one platform-neutral `InputSystem`; it has no SDL dependency and
is included in graphics-disabled builds. The Windows adapter translates SDL
physical scancodes, mouse motion/buttons/wheel, primary-gamepad buttons/axes,
connection changes, and window focus events into canonical `device:name`
controls. The action map combines those controls at `end_frame`, after all SDL
events for that frame have been drained.

Input state and action maps share a mutex because `Engine.run()` releases the
GIL and monitoring Python threads may request pointer lock or inspect state.
Focus loss zeros every held control and the window thread drops relative mouse
mode. A pointer-lock request remains declarative so focus gain can safely apply
it on the SDL-owning thread. No SDL object or event pointer crosses the native
boundary into Python.

## Asset and model ownership

`TextureCache` and `ModelCache` use canonical absolute paths (case-folded on
Windows) as deterministic keys. Texture keys additionally contain linear/sRGB
intent. Cache entries are immutable shared native allocations; clearing a cache
releases only its references. Mutex-protected lookup/load prevents duplicate
resources under concurrent requests. GPU texture and mesh handles remain
private renderer resources released before bgfx shutdown.

The pinned tinyobjloader dependency is private. Easy3D converts parsed OBJ/MTL
data into its own `ModelData`, material, part, and `MeshData` values. Parts are
triangulated and grouped by shape/material. Supplied normals are normalized;
missing normals become per-triangle flat normals. OBJ V is converted to the
engine's top-left UV convention. This model cache is graphics-independent so a
headless process can validate geometry without linking image decoders or bgfx.

## Scene activation and construction contexts

There is no implicit process-global scene. `Entity(scene=scene)` is explicit,
while `with scene:` uses a Python `ContextVar` to provide scoped construction
syntax that is safe across nested and asynchronous Python contexts. Leaving the
context restores the prior scene.

`Game.load_scene(scene)` establishes exclusive game ownership and activates the
scene. A scene cannot be loaded by two games simultaneously. Replacing or
unloading a scene deactivates it without deleting its entities; callers may opt
into clearing on unload. Closing a loaded scene is rejected. `Game` retains the
strong Python scene reference while the native `Engine`/renderer uses a
non-owning pointer, and scene replacement is rejected during `run()`.

## Threading status

Scene mutation is single-gameplay-thread state. The pybind frame bridge
releases the GIL while SDL owns the loop, reacquires it for one Python scheduler
callback after event polling, and returns before native renderer traversal.
`Game` records that thread and callback scope; scene/entity/component APIs allow
running-game mutation only inside that exact boundary. Worker, physics, and
networking systems must use future owned queues instead of mutating the world
from uncontrolled threads.

`SimulationScheduler` retains per-world/entity lifecycle state across repeated
runs. It clamps render delta, accumulates a configurable fixed step, caps
catch-up work, and records dropped time/overruns. Hook iteration uses snapshots;
destroy and clear requests queue until the phase boundary, where `on_destroy`
runs before native invalidation. Newly constructed scripts become eligible at
the next lifecycle preparation boundary.

Callback profiling uses Python's monotonic high-resolution clock and records
calls, total, maximum, and latest duration per hook. Fail-fast exceptions cross
the C++ frame bridge and unwind normal renderer/window RAII. Tolerant mode logs
the traceback once and quarantines that entity for the rest of its lifetime.

## Standalone gameplay utilities

State machines, timers, cooldowns, event dispatch and tweens are pure Python and
do not import the native extension directly. They are deliberately caller
driven: the scheduler does not keep a global timer list or hidden event bus.
Scripts advance simulation-domain objects in `fixed_update`, render-domain
objects in `update`, and explicitly poll wall-domain objects. This preserves
world ownership and makes the utilities usable in headless tests and later
server contexts.

All dispatch is synchronous on the calling gameplay thread. State-machine
callbacks have a reentrancy guard; event dispatch snapshots ordered listeners
and bounds recursive depth. These constraints avoid partially nested state
transitions and unbounded event recursion without introducing worker threads or
an implicit process-global service.

## Physics ownership and fixed stepping

Jolt 5.6.0 is statically linked behind a Pimpl boundary, with CPU/GPU compute,
object streams, debug renderer and profiler disabled. The build uses baseline
SSE2 rather than producing an AVX-specific wheel. Easy3D registers Jolt's global
allocator/factory/types once, while each lazily initialized `Scene` owns a
separate `PhysicsSystem`, layer filters, fixed temporary allocator and
single-threaded Jolt job system. The latter is a correctness-first foundation;
an engine job-system adapter can replace it only after owned worker shutdown and
profiling requirements are defined.

Physics body handles repeat the entity handle safety model with world ID, slot
and generation. A scene clear destroys every added Jolt body before its physics
system and invalidates all handles. Jolt resources contain no renderer state and
the complete falling-body/collision/lifetime regression runs in the
graphics-disabled build.

The scheduler's fixed phase is currently `Python fixed_update → deferred
mutation commit → native CharacterVirtual motor updates → Jolt
PhysicsSystem::Update → dynamic/character entity pose sync →
collision/trigger snapshot dispatch → deferred mutation commit`. Render updates
remain after all catch-up physics ticks.

`Scene` owns a generation-qualified entity-to-body table. Collider creation
builds a static Jolt body from the entity world pose; attaching/removing a rigid
body transactionally replaces that body with dynamic/kinematic or static
motion. Entity destruction removes the body before invalidating the entity.
Static and kinematic entity changes push pose into Jolt, while dynamic pose
changes are accepted only through the explicit teleport API and otherwise flow
from Jolt to the entity after a step. Physics entities reject parenting until a
local/world solver synchronization contract is implemented.

## Physics queries and contact dispatch

Narrow-phase ray, sphere/capsule cast and box/sphere overlap queries execute
synchronously against a scene's Jolt world. Jolt IDs are converted immediately
to generation-checked entity handles; collector storage never crosses the
binding boundary. Native results apply layer/sensor/exclusion filters before
conversion and deterministic sorting.

The Jolt `ContactListener` never calls Python. It copies only user IDs,
world-space contact data, phase and sensor state into a mutex-protected bounded
queue. Queue overflow is surfaced as `PhysicsError` when drained rather than
silently dropping an unbounded workload. The scheduler drains after each
completed physics update and dynamic-pose sync, builds immutable per-recipient
events, invokes callbacks through the existing exception/profiling path, and
commits deferred mutations afterward.

Contact reconciliation tracks which pairs were actually touched each step.
Pairs retired only because all moving bodies slept remain logically active, so
sleep does not fabricate an exit; an awakened pair that is no longer detected
produces the deferred exit snapshot.

## Character motor ownership

Each scene stores generation-qualified entity-to-character records beside its
body records. The physics Pimpl owns Jolt `CharacterVirtual` instances and a
smaller kinematic inner capsule on the character layer. The public handle never
contains a Jolt pointer. Character teardown precedes ordinary body teardown so
Jolt can safely remove the inner body during scene clear.

Input is compact native state: local right/forward movement, camera heading,
and a one-shot jump bit. Per fixed step, the motor applies acceleration or air
control, ground velocity, jump and gravity, clamps velocity against steep
slopes, selects first-person heading or third-person movement-facing rotation,
then calls `ExtendedUpdate` with explicit stair/floor distances. Only the
resulting position, rotation, velocity and ground snapshot cross into scene or
Python state. No Jolt callback invokes Python.

The prediction path adds a separate nonzero uint64 sequence to that same native
input state. A character slot accepts only a strictly newer sequence and updates
its recorded sequence only after ordinary movement/heading/jump validation
succeeds. Slot generation reuse resets it to zero. The offline unsequenced path
remains unchanged.

`PredictedCharacterController` gives client and authority roles the same motor
entry point. A client allocates a monotonic command, applies it immediately and
retains it in a fixed-capacity deque until explicit acknowledgement. An
authority accepts externally sequenced immutable commands and keeps no replay
queue. Queue saturation and uint64 exhaustion fail explicitly. Transport is
caller-owned.

After an authority has stepped an accepted command, it snapshots a monotonic
server tick, acknowledged input sequence, position, normalized rotation and
bounded velocity. Client reconciliation rejects future/backward acknowledgements
and non-newer server ticks, restores that native state, drops the acknowledged
deque prefix and runs the remaining fixed-tick commands through the same
`update_character` routine used by live simulation. Replay advances only that
virtual character against the current collision world; it does not rewind or
advance arbitrary rigid bodies. Correction telemetry records pre-snap position
error and replay work.

Remote actors retain the Phase 4 bounded transform histories. The Phase 5
interpolator derives `render_tick = max(0, authority_tick - delay)` and delegates
to the existing clamped vector/quaternion interpolation, while counting calls
and applied objects. It does not extrapolate or touch the locally predicted
motor.

## Advanced physics resources

Capsule, convex-hull and triangle-mesh settings are converted to Jolt shapes
inside the physics Pimpl. OBJ meshes cross the Python binding only as an asset
path; native model data is combined into one indexed collision shape. Convex
and mesh points are scaled once from the entity transform before body creation.
Jolt shape pointers and triangle acceleration data never enter scene or Python
state.

Constraints have their own world/slot/generation handles and scene ownership
records containing generation-qualified endpoint entities. Fixed and distance
settings lock both Jolt bodies only while constructing the native constraint.
Body removal first removes every referencing constraint; scene maps mirror that
cascade so Python wrappers report stale state rather than retaining a solver
pointer. CCD is an immutable rigid-body creation flag mapped to Jolt
`LinearCast`; changing it requires the same transactional component rebuild as
other construction-time body state.

## Network transport boundary

`NetworkTransport` is the dependency-neutral native data-plane contract. It
accepts an opaque process-local `ConnectionId`, a borrowed payload that the
implementation must consume or copy before returning, and reliable/unreliable
delivery intent. Sends return explicit queued/invalid/oversize/full outcomes;
they do not hide backpressure behind an unbounded allocation. Connection IDs
are neither entity handles nor future replicated network-object IDs.

Transport implementations publish copied `connected`, `disconnected`, and
`message` events through `TransportEventQueue`. The queue is mutex protected,
FIFO, and capacity bounded. An overflow is counted and surfaced as
`NetworkError` when the owning transport is polled. A future socket worker may
write this queue, but it must not call Python or mutate scenes. Python polls
immutable snapshots on its owning gameplay thread.

`SimulatedNetwork` provides two endpoints behind the same interface. Its
seeded clock schedules bounded messages with one-way latency, jitter and loss,
preserves a monotonic sequence for equal-time ordering, and records sent,
received, lost, byte, rejection and overflow counters. It is a deterministic
datagram impairment tool: reliable intent is metadata and is not retransmitted
by the simulator.

Representative `NetworkCondition` profiles bind names to validated one-way
lag, average jitter and packet-loss probability. They can construct the exact
seeded simulator above. A separate `BackendImpairment` scope maps the same
values to GameNetworkingSockets' official global fake-send lag, jitter and loss
controls, allowing its real reliable ordering/retransmission to operate. The
scope uses a process lock, rejects nesting/concurrency and clears settings on
all exits. GNS must already be alive; these global controls are for isolated
tests, never per-client production policy.

Phase 3.2 links GameNetworkingSockets 1.6.1 and a source-matched Protobuf 5.29.3
runtime statically. Windows BCrypt supplies platform crypto, ICE/WebRTC remains
off, and a reference-counted process owner serializes native initialization and
shutdown. A real reliable socket-pair smoke test validates that private backend.
The Phase 3.4 live client adapter now places backend callbacks behind the
existing bounded queue; it does not call Python or mutate scenes from the
native callback path.

The Phase 3.3 handshake is now a native transport-independent state machine.
Its 12-byte fixed envelope and peer declaration use explicit little-endian
fields, exact protocol/schema compatibility, client/server role checks and a
negotiated minimum payload limit. The three-message client hello/server
accept/client confirm exchange prevents the server from declaring completion
before it verifies the client's negotiated limit. Malformed peer data produces
stable bounded disconnect codes rather than exceptions escaping the network
input path.

`NetworkClient` owns one GNS handle and one handshake instance. Connection IDs
are monotonically generated local identities, invalidated on close, and never
derived from GNS handles. `poll()` is the sole pump: run connection callbacks,
copy a bounded number of messages, apply the handshake/deadline, surface queue
overflow, then drain immutable events. Python `Client` converts those events
and invokes optional callbacks only after returning from native GNS code on the
same owning thread. The native callback finds its owner through per-connection
GNS user data; shutdown clears that pointer before closing the handle so queued
callbacks cannot target a destroyed client.

`NetworkServer` applies the same boundary to many peers. One native listener
and poll group own a bounded handle→peer map; each peer owns its server-side
handshake, deadline, negotiated limit and monotonically generated local
`ConnectionId`. Handshaking sockets count against the configured maximum but
are absent from the application connection list. The server closes accepted
peers before its listen socket so GNS cannot replace graceful application
reasons with listener teardown. The Python `Server` composes this transport
with `SimulationScheduler` and a `Scene`; it deliberately never creates
`Engine`, `Input`, a platform window or a renderer. `run()` is a paced fixed-
rate loop, while `step()` is an exact one-tick integration seam for tests.

`ListenServer` is composition, not a third authority implementation. Its
`authority` is the only scene/scheduler owner and its `client` is the same
loopback transport used by a remote process. An internal per-tick pump runs the
client only after the authority completes one tick. Tagged role events prevent
coincidentally equal local connection numbers from becoming shared identity,
and `local_host` distinguishes the private peer from later remote clients.
This keeps listen-host callbacks from executing authoritative Python logic or
physics twice.

LAN discovery is deliberately outside the gameplay transport. A pure-Python,
poll-owned IPv4 UDP control plane sends a bounded nonce query and receives a
bounded unicast description; no discovery thread or socket enters the native
GNS callback path. The announcer caps work per poll and keeps a finite LRU of
per-source response timestamps. The browser accepts only its current nonce
during a finite window and stores a finite TTL/LRU result cache. A result is
only an address suggestion: the caller must explicitly pass its numeric address
and game port to `Client.connect()`, where the ordinary protocol handshake
still applies.

Phase 3 process integration launches the installed extension in independent
Python processes rather than constructing two owners in one interpreter. The
sample and tests publish readiness only after a real bind or each side's
application-level handshake event. That distinction prevents a client
confirmation from being mistaken for server-side establishment. GNS
`TimeoutConnected` is configured per client/listener through the public
`peer_timeout`; application code continues to observe liveness changes only
when its owner polls. Abrupt process tests deliberately use OS termination and
assert copied disconnect events without assigning stable meaning to backend/OS
failure codes.

The first replication layer composes existing `Server`/`Client` owners rather
than changing transport identity. A frozen `PrefabRegistry` is schema: explicit
prefab ID/name pairs and its declared version form a canonical fingerprint.
`ServerReplication` is the only network-object ID allocator and uses monotonic
uint64 values unrelated to generation-qualified scene IDs. It creates and
destroys authority entities, then emits reliable fixed-size lifecycle frames.

Late join is a begin/spawn/end stream with declared count, schema, fingerprint
and epoch. Reliable ordering places user callback spawns after the completed
snapshot. `ClientReplication` validates the stream before declaring sync and
owns only client-scene replicas. A failed send disconnects the affected peer;
it never converts partial lifecycle delivery into silent success. This layer
does not yet serialize component values or grant client authority.

Network variables extend the frozen prefab fingerprint with canonical field
ID/name/type/default/bound definitions. Each replicated object owns separate
authority or client mirror state. Authority changes normalize through the same
bounded codec used on receive, increment per-field versions and become dirty;
flush sends only dirty state. Snapshot values are streamed after each spawn and
uniquely accounted before end, avoiding an object-count-sized frame buffer.
Client setters fail locally and stale/duplicate/type-mismatched updates fail the
connection rather than mutating state.

Transform replication is a separate replaceable stream rather than generic
fields. A prefab opts into the fixed local position/quaternion/scale schema.
The authority samples at explicit nondecreasing simulation ticks and sends one
monotonic-sequence frame over unreliable delivery. Client replicas retain
fixed-capacity per-object histories, discard reordering/duplicates, clamp at
history endpoints, and interpolate vectors plus normalized shortest-path
quaternions at an explicit render tick. A per-connection predicate provides the
first relevance seam; it suppresses transform bandwidth only, leaving reliable
lifecycle and variables coherent. This stage deliberately has no extrapolation,
client prediction, ownership, reconciliation or spatial index.

RPCs extend the same frozen prefab fingerprint with stable IDs, direction,
positional primitive bounds, delivery, ownership and rate policy. A call frame
names only a known network object and RPC ID; it cannot name/import a Python
callable. The authority validates object/schema/direction, caller-monotonic
sequence and optional owner connection before rate accounting and handler
dispatch on the existing poll thread. Client dispatch validates the inverse
direction and authority sequence. Reliable/unreliable selection changes
delivery only, never authority. Application handlers remain responsible for
scene/game-condition validation beyond the engine's schema and ownership gate.

Replication peers become live-update recipients only after the authority has
queued their complete initial snapshot. This readiness set is separate from the
transport's established connection set: a native poll may establish several
peers before their Python connect callbacks run. Spawn/value/transform/RPC
broadcasts target only snapshot-ready peers, preventing a later callback's peer
from receiving a live spawn before its snapshot begin. Reliable ordering then
places subsequent live state after that peer's queued snapshot end.

Explicit resync reuses this same readiness boundary. A replay-guarded client
control frame temporarily removes only that peer, streams a new complete
snapshot and re-adds it on queue success. No client state is accepted and no
parallel delta-patch format exists. Healthy peers continue receiving live state
throughout another client's rebuild.

Replication wire version 2 adds per-object transform ACK, compact delta and
baseline-recovery controls. Authority may delta only from a snapshot ACKed by
that exact connection. Position uses signed int16 centimeters, quaternion
component differences use 1/16000 units and scale uses 1/1000 units; overflow or
invalid reconstruction falls back to a full float32 snapshot. Authority stores
the quantized reconstruction—not the ideal source—as the sent snapshot so an
ACK selects exactly the state held by the client. Sent history is bounded to 32
snapshots per connection/object; client history retains its configured 2–256.
If the named baseline is gone, the client drops that delta, sends a monotonic
reliable request, and the authority clears only that baseline so the next
relevant update is full.

Replaceable transform work uses a per-connection tick-refilled token bucket.
Stable ordering combines an optional finite application priority with
`SpatialInterest` distance priority and object ID as tie-breaker. Out-of-radius
objects retain reliable lifecycle/fields and their last transform; interest is
not a visibility/despawn authority policy. Budget exhaustion defers transforms
and is reported, while critical reliable streams are intentionally not dropped
to meet a cosmetic bandwidth target.
